# Generate Changelog

## 与 Devlog 的区别

|      | Devlog              | Changelog                    |
| ---- | ------------------- | ---------------------------- |
| 读者 | 开发者、AI          | 用户、使用者                 |
| 内容 | 开发过程、技术决策  | 用户可感知的变化             |
| 粒度 | 细，含"为什么"      | 粗，只写"是什么"             |
| 文件 | `.devlog/DEVLOG.md` | `CHANGELOG.md`（项目根目录） |

---

## Workflow

1. 检查 `CHANGELOG.md` 了解已记录的版本
2. 确定 commit 范围：

```bash
   git tag --sort=-version:refname | head -5        # 查看已有 tag
   git log <last_tag>..HEAD --oneline --no-merges   # 上次 tag 到现在
```

3. 判断发布状态：
   - **HEAD 已打 tag**：使用版本号作为标题，如 `## [v0.2.0] - 2026-05-29`
   - **HEAD 未打 tag**：使用 `## [Unreleased]` 作为标题，待发布时替换
   - 当发现git tag的最新tag版本高于 `CHANGELOG.md` 的中的最新记录则不使用 `## [Unreleased]` 而是使用最新的git tag 版本

4. 检查 `CHANGELOG.md` 是否已有 `[Unreleased]` 块：
   - **有**：将新变更合并追加到该块，不新建
   - **无**：在文件顶部插入新块

5. 过滤对用户无感知的变更（重构、CI、格式化、依赖更新等），按用户视角归类写入
6. 如果本次变更包含**新增**分类，读取项目根目录 `README.md`：
   - 找到合适的位置（如 `## Features` 或 `## 功能` 章节）追加新功能描述
   - 如果 README 没有 Features 章节，在文件末尾新增 `## Features` 并写入
   - 保持 README 原有的语言风格和格式
   - **只追加新功能，不修改已有内容**

---

## File Operation

| 文件           | 路径       | 写入方式                                  |
| -------------- | ---------- | ----------------------------------------- |
| `CHANGELOG.md` | 项目根目录 | 新版本插入顶部；`[Unreleased]` 块合并追加 |
| `README.md`    | 项目根目录 | 仅有新增功能时，追加到 Features 章节      |

**README 更新规则：**

- 只在有**新增**功能时才修改 README
- 优化、修复、破坏性变更**不触发** README 更新
- 追加内容风格与 README 现有内容保持一致
- 若 README 无 Features 章节，自动创建后追加

## Output Rules

- 使用中文 + Markdown
- 只写用户能感知的变化，不写技术实现细节
- 语言简洁直接，避免技术术语
- 破坏性变更必须单独标注
- 新版本插入文件**顶部**（`# Changelog` 标题之后）
- `[Unreleased]` 块全局只能有一个
- **绝不覆盖**已有版本记录

---

## Format

```md
## [vX.Y.Z] - YYYY-MM-DD ← 已发布

## [Unreleased] ← 未发布

### 新增

- ...

### 优化

- ...

### 修复

- ...

### 破坏性变更

- ...

（无内容的分类省略）
```

**完整文件结构（混合状态示例）：**

```md
# Changelog

所有版本的变更记录。

---

## [Unreleased]

### 新增

- 剪贴板监控：自动检测剪贴板变化并弹窗提示

---

## [v0.1.1] - 2026-05-27

### 新增

- 主题系统：支持亮色 / 暗色 / 跟随系统

## [v0.1.0] - 2026-05-20

...
```

---

## 分类标准

| 分类           | 写什么                             | 不写什么               |
| -------------- | ---------------------------------- | ---------------------- |
| **新增**       | 用户能用到的新功能                 | 内部模块、工具函数     |
| **优化**       | 体验提升、性能改善、UI 调整        | 代码重构、架构调整     |
| **修复**       | 用户遇到的 bug                     | 内部错误处理、边界情况 |
| **破坏性变更** | 配置格式变更、API 变更、行为不兼容 | —                      |

## 其他补充

可参考 git-commit skill 中的规则进行git相关操作

## Example Output

```md
# Changelog

所有版本的变更记录。

---

## [Unreleased]

### 新增

- 快捷键自定义：支持在设置中修改所有快捷键

---

## [v0.1.1] - 2026-05-27

### 新增

- 主题系统：支持亮色 / 暗色 / 跟随系统

### 优化

- 新增关于页面，展示版本信息和更新日志入口

### 修复

- 修复首次启动时设置未保存的问题
```
